# 에이전트 고도화 보고서 — 일일 AI Agent 브리핑 에이전트

작성일: 2026-10-01 · 작성자: 송환혁

## 요약

기획서의 브리핑 에이전트(GeekNews·AWS ML Blog 수집 → 정제 → 브리핑 초안 → `briefings/YYYY-MM-DD.md` 아카이빙)를 deepagents 하네스 위에 스킬·메모리로 구현하고, 실행마다 trace 를 남기는 Observation 을 붙였습니다. 질문-평가기준 세트(6개 사례)로 baseline 을 2회씩 실행한 결과 11/12 통과였고, 유일한 실패는 "에이전트와 무관한 글(인물 가십·모델 리전 소식) 포함"이었습니다. 이를 겨냥해 스킬 정제 규칙 2줄을 추가한 v1 을 같은 조건으로 실행했으나 결과가 11/12 로 같고 개선이 재현되지 않아 **무승부로 판정, promote 하지 않았습니다**. 실험 과정에서 평가기 결함 3건을 발견해 평가셋 v2 로 보정했습니다.

## 실험 설계

- **목표**: 브리핑이 기획서 규칙(근거 기반, 무관 글 제외, 투자 권유 금지, 발송 전 아카이빙)을 지키는지 세트로 검증
- **가설**: 정제 단계에 "본문 주제가 에이전트가 아니면 제외(모델 리전·가용성, 일반 모델/RAG 소개, 인물 가십)"를 명시하면 core-01 의 관련성 실패가 사라진다
- **비교**: baseline 과 v1 에 동일 질문 6개를 각 2회 격리 실행(메시징 커넥터 off). v1 은 SKILL.md 에 2줄만 추가(`evals/results/v1.diff`)
- **채점**: 룰 기반 + judge(`z-ai/glm-5.3`, 에이전트 `kimi-k3` 와 다른 계열로 자기채점 편향 완화). `required` 기준 하나라도 실패 시 사례 FAIL

## 평가셋 v1 → v2 개선

| 이전에 틀리거나 모호했던 점 | 개선 후 |
| --- | --- |
| 항목 수를 링크 수로 세서, 같은 발표 2건을 한 항목에 묶은(스킬 지시대로) 브리핑을 "6건"으로 오판 | 번호 붙은 항목 제목(`##`/`### N.`) 수로 판정 |
| 추론형 judge 가 8,000 토큰을 전부 추론에 써서 빈 응답 → 기준 전체가 "실패"로 기록 | `reasoning_effort=low`, 재시도 3회, 그래도 판정 못 한 기준은 실패가 아닌 **미검증** → 비교 시 inconclusive |
| judge 에게 수집 후보 요약을 160자만 보여줘, 원문에 있는 고유명사(AgenticRetrieveStream)를 "지어낸 것"으로 오판 | 후보 요약 400자까지 제공 |

세 결함 모두 에이전트 재실행 없이 저장된 실행을 `grade` 로 재채점해 확인했습니다(최초 7/12 → 보정 후 11/12).

## 판정 및 반영

- **판정: 무승부(tie) → promote 하지 않음, baseline(본체) 유지.** v1 은 회귀는 없지만, 핵심 사례의 개선이 2회 반복에서 재현되지 않았습니다.
- **원인 해석**: 관련성 판단의 흔들림은 규칙 문구보다 "에이전트 단어가 들어간 비(非)에이전트 글"을 LLM 이 매번 다르게 해석하는 데서 옵니다. 문장 규칙 한 줄로는 경계를 고정하기 어렵습니다.
- **다음 가설(v2 후보)**: ① 정제 단계에서 후보마다 `include/exclude + 근거`를 먼저 표로 쓰게 하는 2단계 절차, ② 제외 예시(가십·리전 확장·일반 모델 출시)를 references 에 few-shot 으로 추가. 반복 3회로 재현성을 확인한 뒤에만 promote 합니다.
- **한계**: 사례당 2회 반복이라 통계적 확신은 낮고, judge 판정 자체도 비결정적입니다. RSS 가 실시간이라 실행 시점에 따라 후보가 달라질 수 있습니다(같은 날 실행으로 완화).
