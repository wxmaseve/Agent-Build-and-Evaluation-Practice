## 2. 에이전트로 도움받을 부분 찾기

### 찾아볼 관점 적용

| 관점 | 적용 내용 |
|---|---|
| 정보 찾기 | GeekNews, AWS 기술 블로그에서 "AI Agent" 관련 최신 글 수집 |
| 초안 작성 | 수집된 글의 요약 + 일별 트렌드 브리핑 초안 생성 |
| 형식 변환 | 브리핑 초안을 메일 본문 / 슬랙 메시지 포맷으로 변환 |
| 오류 검토 | 링크 중복 제거, 접근 불가 URL 필터링, 무관 글 제외 |
| 반복 실행 | 매일 정해진 시간(오전 8시 KST)에 수집 → 작성 → 발송 |
| 결과 정리 | 브리핑 원문을 날짜별 파일로 아카이빙 |

### 예시: 일일 AI Agent 브리핑 업무 중

에이전트가 도울 수 있는 부분
- GeekNews에서 AI Agent 관련 게시물 URL·제목·코멘트 수 추출
- AWS Blog(AI/ML 카테고리) 최신 포스트 크롤링 및 요약
- 중복 제거 → 중요도(코멘트 수, 게시 시간, 키워드 매칭) 정렬
- 브리핑 초안 작성 (제목 + 2~3줄 요약 + 원문 링크 + 주목 포인트)
- 슬랙/메일 형식 변환 후 발송, `briefings/YYYY-MM-DD.md`로 저장

사람이 할 부분 (자동화하지 않음)
- 브리핑을 읽고 관심 항목을 깊게 따라가기
- 요약 품질 피드백 → 키워드/규칙 조정

> 원칙: 전체 파이프라인 자동화보다, 먼저 "수집 → 요약 초안 생성" 구간을 1단계로 검증한다.

## 4. 반드시 지켜야 하는 규칙

1. 허위 요약 금지 — 반드시 원문에 근거한 내용만 작성
2. AI Agent와 무관한 글은 제외, 애매하면 판단 근거를 명시
3. 투자 매수/매도 권유 금지 — 기술 트렌드 정보 제공만
4. API 키, 웹훅 URL 등 자격증명을 파일에 저장하지 않음
5. 발송 전 브리핑 원문을 날짜별로 아카이빙 (workspace/briefings/)
6. 한국어 작성, 기술 용어는 원어 병기, 간결·사실 중심 톤
7. 전체 자동화 전 1단계(수집→초안) 품질 검증을 먼저 통과해야 함

## 6. 검증 결과 (2026-09-30, 1단계 수동 실행)

### 실행 내용

실제 파이프라인을 1회 수동 실행하여 "수집 → 정제 → 브리핑 초안" 구간의 품질을 검증했다.

- 결과물: `workspace/briefings/2026-09-30.md`
- 보조 보고서: `workspace/reports/2026-09_top-ai-lab-announcements.md` (톱티어 발표 상세)

### 단계별 검증 결과

| 단계 | 결과 | 상세 |
|---|---|---|
| GeekNews 수집 | ✅ | RSS(https://news.hada.io/rss)로 50건 수집, 동적 관련성 판단으로 12건 선별 |
| AWS Blog 수집 | ✅ | AgentCore 런타임(9/18) 등 최신 Agentic AI 포스트 확인 |
| 톱티어 동적 쿼리 | ✅ | Meta Muse 개인 에이전트 포함 5개사(OpenAI·Anthropic·xAI·Google·Meta) 9월 발표 수집 — 하드코딩 키워드 없이 신규 발표 포착 확인 |
| 정제·중복 처리 | ✅ | DevDay 관련 다발 병합, 원문 요약만 사용(허위 요약 없음) |
| 브리핑 초안 품질 | ✅ | 항목 구조(제목+요약+링크+주목 포인트) 준수, 핵심 요약 3줄 배치 |

### 검증에서 발견한 개선점

1. **GeekNews RSS에 코멘트 수 미포함** — 중요도 정렬에 필요하므로, 상위 후보만 상세 페이지(`/topic?id=`)를 저빈도(3~5초 간격)로 조회해 보완한다.
2. **단발성 소식의 배제 기준 필요** — "Claude 일부 장애" 같은 일시적 사건은 트렌드 가치가 낮으므로, "지속적 영향 여부" 기준으로 배제한다.
3. **AWS Blog는 웹 검색보다 RSS/카테고리 구독이 안정적** — 카테고리별 RSS로 상시 수집 전환한다.
4. **GeekNews robots.txt 정책** — AI 학습 봇은 차단되어 있으므로, 일일 1회 저빈도 브리핑 용도로 유지하되 대량 크롤링은 하지 않는다.

### 결론

- 1단계 목표(수집 → 요약 초안 생성)는 품질 기준을 통과했다.
- 동적 쿼리 방식이 실제로 신규 발표(Meta Muse 등)를 놓치지 않음을 확인했다.
- 다음 단계(2단계): 발송 채널 연결 → 개선점 반영 → 자동 스케줄링(매일 08:00 KST) 활성화.
